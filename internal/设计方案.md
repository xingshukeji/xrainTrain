# XRain 独立培训课程设计方案

Status: Proposed

更新日期：2026-10-25

任务类型：Development，当前交付为需求与设计复查

项目：`xrainTrain`；独立工程：`D:\github.com\xrainTrain`

仓库：[xingshukeji/xrainTrain](https://github.com/xingshukeji/xrainTrain)，默认分支 `main`

## 1. 设计结论与授权范围

培训作为独立产品建设，拥有独立仓库、课程网站、依赖、构建、发布和学习记录。培训内容不放入 Workforce、铵帮或其他业务源码仓库，也不并入 LLMTrain。用户已确定使用 `D:\github.com\xrainTrain`；该目录已有独立 Git 仓库，`origin` 指向公开仓库 `xingshukeji/xrainTrain`，默认分支为 `main`。本方案和[能力与接口学习地图](能力与接口学习地图.md)保存在该工程的 `internal/`，课程站点与发布工作流尚待实现。

课程面向会编程、理解基本数据库和 HTTP，但不了解 XRain 低代码机制的开发与维护同事。课程把传统开发经验连接到业务建模、元数据源码、应用包、租户安装、平台查看和 Workforce 开发。低代码平台源码保持闭源。

本次交付是可评审的产品需求与设计方案。已确认要求包括：培训独立、课程与业务源码分开、平台源码不开放、示例像 Getting Started 一样特别简单、完整考虑能力与接口资料，以及多用 SVG 绘制必要且正确的流程。最终交付必须能够独立运行，并同时提供独立 GitHub 仓库和在线课程网站。本方案按用户指定的工程和 LLMTrain 已验证的部署方式，采用 VitePress、GitHub Actions 与 GitHub Pages。

完整交付包含可复现的课程源码、可运行的网站、经核验的最小练习、GitHub 仓库和真实可访问的课程网址。只完成设计文档、源码上传、构建成功或演示首页，都不足以宣告课程完成。本轮执行范围是迁移设计资料并按已确定工程修订方案；课程代码和网站部署尚未实施。仓库与项目名称已经确定，首版按公开静态课程设计，实际网站地址以首次 Pages 成功发布的输出为准。

所有新概念先用最小示例解释，每次只增加一个学习变量。首页直接进入 Getting Started，先完成第一次可见结果，再解释原理与扩展。课程同时提供完整的能力地图和接口文档入口；初学者需要知道各类能力解决什么问题、资料在哪里，基础课要求亲手使用常用接口，其他接口按职责和场景深入。Workforce 协作任务放在后续综合练习。

课程解决必要知识的缺口。平台缺少查看入口、运行版本无法确认或错误缺少定位信息时，相应产品维护者负责修复。课程不能以增加学习要求来掩盖这些缺口。

## 2. 学习目标与产品需求

课程要让初学者从“能照做”走到“能查文档并独立完成一个小功能”。完成基础课后，学习者应能解释对象定义与记录值，查明当前身份和目标，找到正确接口，完成简单读写与查询，核对安装版本，并依据返回结果定位一处错误。进入综合练习后，再要求追踪业务源码、页面和接口消费者。

| 学习者 | 建议路线 | 能力出口 |
|---|---|---|
| 开发与维护同事，初次接触低代码 | Getting Started → 基础单元 → 综合练习 | 先做成一个最小示例，再理解、修改并定位实际业务 |
| 已了解低代码的工程师 | 从能力地图或接口文档入口进入，按练习判断跳读位置 | 能选择合适能力、核对实际版本和接口合同 |
| 平台或交付维护者 | 主课后按职责阅读身份、安装恢复和交付专题 | 能解释并检查所负责环节 |
| 普通业务使用者 | 后续单独提供业务使用教程 | 完成自身业务操作；不要求学习包构建与源码 |

数学、模型训练、低代码引擎实现和完整平台运维不作为主课前置知识。主课遇到必要术语时就地解释，再提供速查入口。

| 用户需要完成的事 | 产品必须提供的内容 | 可观察的完成结果 |
|---|---|---|
| 第一次做出结果 | 一篇连续的 Getting Started、完整最小样例、明确前置和真实查看入口 | 学习者独立保存并重新读到一条便签 |
| 打开就能学，下载后能运行 | 可访问的在线课程，以及 GitHub 中完整的站点源码、锁文件和运行说明 | 在线完成学习操作；从 GitHub 获取干净副本后可独立安装、启动和构建 |
| 知道平台能做什么 | 按业务问题组织的能力地图，每项标明学习深度和适用范围 | 能判断问题属于模型、数据、权限、逻辑、集成或交付 |
| 知道去哪里找接口文档 | 常驻的“接口文档”入口，区分 HTTP、动态目录、CLI、SDK 和应用包格式 | 从“读取一条便签”找到方法、路径、身份要求和返回合同 |
| 看懂并调用接口 | 用同一条便签讲请求、响应、标识、分页和错误；同时显示实际证据 | 能读写记录，区分元数据 ID 与记录 ID，并解释失败 |
| 做一个小改动 | 一次只改变一个字段、值或条件的练习 | 能预测结果，完成回读，发现不符合预期的地方 |
| 知道如何扩大功能 | 函数、事件、定时、集成、附件和 AI 等能力的短例子与深入入口 | 能选择下一项能力，知道需要补哪些配置和权限 |
| 遇错后继续工作 | 按现象查找的排错材料及失败后的下一项检查 | 无须维护者口头指路，也能定位第一处偏差 |
| 隔一段时间回来继续 | 搜索、稳定导航、术语、适用版本和本地学习记录 | 能从未完成内容或具体问题继续，不必重读全部课程 |

“覆盖全部资料”按资料类别和能力范围验收，不按记住全部端点验收。所有已经提供给开发者的相关文档都应能从课程定位；暂缺文档的能力登记缺口。入门地图不冒充平台所有 API 的完整清单，具体范围见配套地图。

## 3. 独立项目与职责边界

| 对象 | 培训项目负责 | 与其他项目的关系 |
|---|---|---|
| 课程正文 | 讲解、图解、案例、练习、术语和排错材料 | 根据公开契约和可访问业务源码编写；标明适用范围 |
| 能力与接口导航 | 按学习问题连接能力、资料、课程和练习 | skills-hub 保持能力参考的原所有者；平台及 SDK 所有者维护正式接口合同 |
| 课程网站 | 导航、搜索、阅读、交互演示、答题和本地学习记录 | 独立安装、构建、预览和发布，不加载业务应用 |
| GitHub 交付与在线发布 | 独立仓库、构建检查、发布流程、版本和访问地址 | GitHub 托管课程项目；网站发布同一提交构建出的产物，不改造业务项目流水线 |
| 业务源码与正式契约 | 仅建立来源引用，必要时展示短小教学片段 | 原仓库仍是业务事实所有者；课程不复制完整源码树或正式文档库 |
| 平台与应用操作 | 解释既有管理界面、公开 CLI 和 API | 在对应系统执行；课程网页不代替平台安装、授权或业务写入 |
| 真实练习 | 提供最小教学样例、步骤、预期结果和排错线索 | 入门样例独立于业务工程；综合练习再引用原业务仓库的指定基线 |
| LLMTrain | 借鉴连续课程、术语提示、图解、练习及已验证的静态发布方式 | 保持两个独立产品；使用 xrainTrain 自己的依赖、配置与发布目标，不要求运行时或构建时访问 LLMTrain |

独立工程采用以下职责划分。当前已有根 README 和 `internal/` 内的两份设计资料，其余目录和运行文件在课程实现时建立：

```text
xrainTrain/
  course/          课程、练习、能力地图、接口文档入口与速查
  course/public/   课程使用的脱敏图片和媒体
  examples/        最小教学元数据和必要示例文件，不放业务工程副本
  .vitepress/      课程站点配置与教学交互组件
  .github/workflows/  课程自己的检查、构建与网站发布流程
  internal/       课程设计、来源对应、内容审阅与维护资料
  package.json    培训站点自己的依赖和构建入口
  pnpm-lock.yaml  固定课程依赖，供本地与 GitHub 构建复现
  .gitignore      排除依赖、缓存、构建输出及本地环境资料
  README.md       课程定位、维护和本地预览入口
```

教学片段与最小样例用于解释机制，不承担生产实现。Getting Started 提供可单独获取的完整最小示例，不要求下载 Workforce 或铵帮源码。综合练习才使用原业务仓库的指定基线或其正式交付物，在学习者的独立目录执行。课程构建不读取相邻业务目录，不使用业务仓库作为工作区依赖，也不从业务源码实时生成课程正文。

设计资料归入 `internal/`，本方案是需求和范围的唯一所有者；学习地图在实现时转换为网站中的能力与文档查阅入口。网站采用 `srcDir: "course"`，只构建课程及所需资源。当前 GitHub 仓库公开，`internal/` 内提交的文件同样公开；这里仅保存可公开的设计和来源引用，不存放秘密或私有原文副本。Workforce 后续只链接课程入口；课程构建和浏览不依赖本地存在 skills-hub 或业务仓库。

## 4. 从 Getting Started 开始

建议入门使用“我的第一条便签”：一个自定义业务对象“便签”、一个自定义文本字段“内容”、一条记录“你好，XRain”。完整样例预先填写包身份、版本和必要声明，并说明用途；平台自动生成的系统字段不在样例中重复定义，课程说明其查看方式。简单指学习者需要理解的业务范围小，不表示可以省略平台真实要求。

首课只完成“看懂最小定义 → 构建并安装 → 在平台写入和查看一条记录”。不要求先学习全部架构、编写前后端、开发登录、配置多人协作、接入 AI 或理解发布流水线。真实练习需要的运行平台、目标和身份作为明确前置条件提供，准备环境单列为按需帮助。

学习顺序为 Getting Started → 基础必做 → 按需专题 → 实际工程。能力地图用于选择学习内容，接口文档入口用于查具体合同；两者不增加首次开始前的必读步骤。基础单元沿便签逐项展开；选项、关联等扩展示例分别提供自己的最小起点，不把所有功能累加成一套越来越大的业务。

| 单元 | 建议课程内容 | 学习者要解释的问题 | 可观察成果 |
|---|---|---|---|
| G0 我的第一条便签 | 获取最小示例，安装并保存“你好，XRain” | 定义一个字段，为什么还需要创建一条记录 | 在真实平台看到对应字段和这条记录，并说出它们的区别 |
| B1 刚才发生了什么 | 对象、字段、记录、系统字段、文件、包和租户 | 定义、已安装定义和记录值分别是什么 | 用同一张小图解释刚才完成的动作，找到 recordId 和有效字段 |
| B2 去哪里查接口，怎样读 | 从问题选文档；读取方法、路径、参数、身份、返回和错误 | HTTP、CLI、SDK、包格式是否能互换 | 自己找到对象 describe 与单条记录读取合同，解释两者差别 |
| B3 用接口读写同一条便签 | 新增、回读、修改、分页、一个筛选条件；删除单独说明 | 页面与接口是否访问同一条数据 | 保存后回读同一 recordId；按条件查到预期记录 |
| B4 每次认识一种字段 | 名称与 API 名、文本约束、常见类型；选项、关联各用独立小例子 | 字段类型、显示方式与保存值有什么关系 | 根据 describe 和设计标准选择类型，解释 label、value、ID 的区别 |
| B5 当前身份为什么能做这件事 | 登录、租户、应用准入、对象/字段/记录权限与执行身份 | 登录成功为什么仍可能被拒绝 | 读取自身上下文，根据既定允许/拒绝例子定位权限层，不改用管理员验证 |
| B6 改定义怎样生效 | 沿最小样例解释构建、导入、安装、版本及有效定义 | 改记录、改模型和更新宿主程序分别改变什么 | 完成一个小定义变更，核对目标安装和字段，并保留已有记录 |
| B7 出错后怎样继续 | 输入错误、无权、找不到、并发冲突、服务错误；AI 辅助查证 | 第一处偏差在哪里，下一步读什么 | 保留输入和实际返回，独立选出检查动作，再核对 AI 建议 |

各单元按独立学习问题拆分，不预先固定课数。Getting Started 先完成一篇；首版完整交付还须包含能力地图、接口文档入口和基础课，不能以一篇入门页代替完整培训产品。重复或过薄的页面合并。

初学者还应认识函数、编排、Trigger、Routine、外部集成、文件、通知、个人邮箱和 AI 接入分别解决什么问题，知道其文档在哪里。动手深度按[能力与接口学习地图](能力与接口学习地图.md)选择。每个后续专题仍从最小例子开始，例如一个固定输入函数、一次读取型编排或一个定时查询；不直接从销售全流程开始。

综合练习再对照 Workforce 的 `workforce__task__c`、`description__c` 及实际消费者。身份管理、复杂授权、安装恢复和交付维护归相应职责专题，不要求所有初学者执行管理动作。

### 接口文档是常用入口

站点导航常驻“接口文档”。首页、每个接口练习和排错页均可进入；不能把文档入口埋在课程末尾。入口先回答“你想做什么”，再指向现有说明、目标实际目录和对应最小例子。搜索覆盖业务用语、中文标签、API 名和常见错误码。

每项文档入口说明：适用对象、解决的问题、所属系统、访问条件、来源与适用版本。HTTP 接口教学必须展示方法/路径、认证与租户、输入、成功响应、失败响应，以及是否改变数据或产生外部动作。SDK 类型和 CLI 输出分别解释，不套用统一响应封装。

接口族、现有静态资料、在线发现路径、公开 SDK 与 CLI 的对应关系由配套地图维护。课程只解释必要片段和读法；不复制维护第二份完整 API 规范。正式网站采用学习者可访问的已核验链接；本设计稿的相邻仓库路径只用于本地评审。

## 5. 最小示例及“古法”解释

入门例子的业务内容仅包含：

```text
对象：便签
字段：内容（文本）
记录：你好，XRain
```

这是教学示例的设计，不是可直接提交给平台的文件。正式课程提供经真实构建和安装验证的完整示例文件，使用平台已有工具，不让学习者把省略字段的示意片段当成完整源码。

Getting Started 按以下动作组织。课程正文中的命令、菜单和结果必须在制作时核验，不在设计稿中猜测：

| 动作 | 学习者做什么 | 看到什么 |
|---|---|---|
| 1 看最终结果 | 看一张只有“内容”和“你好，XRain”的结果图，确认本课目标 | 知道自己最后会做出什么 |
| 2 获取示例 | 打开完整最小示例，只定位“便签”和“内容”的定义 | 认识一个对象和一个文本字段 |
| 3 构建应用包 | 用已有构建入口处理该示例 | 得到具有明确身份和版本的 `.appkg` |
| 4 导入并安装 | 按实际入口将该包安装到已准备的练习目标 | 安装成功，平台中可找到便签对象和内容字段 |
| 5 写入并查看 | 在已核验的数据入口填写“你好，XRain”，保存后重新打开 | 看到同一条已保存记录 |

每步只交代当前动作、必要输入和预期结果。首轮不展开完整参考手册；读者需要时可查看某个必需声明的解释。构建、导入和安装的真实差别仍保留，不另写隐藏这些动作的一键教学脚本。

现有 `xrain-cli` 支持应用包初始化和构建，没有安装命令。首课的导入与安装必须指向已核验的管理界面或公开操作入口。新对象不保证已经带有列表视图；课程作者须验证实际的数据查看与录入路径，不能只凭元数据定义宣称页面已生成。

首课完成标准：学习者亲自看见对象、字段和一条保存后可再次读取的记录，能够说出“内容是字段定义，‘你好，XRain’是记录值”。网页演示只能证明案例判读，不能代替这个真实操作结果。

首课之后每次只增加一个变化，例如把记录内容改为“我的第二条文字”；再在另一练习中学习修改字段说明。关联对象、多角色、状态流转、触发器、任务协作和 AI 都按需逐项引入。

课程先用工程师熟悉的概念建立直觉，再回到真实对象与契约：

| 传统经验 | XRain 中的解释 | 必须保留的区别 |
|---|---|---|
| 表、列、记录 | 业务对象、字段定义、业务记录 | 逻辑对象不等同于已知的物理表实现；字段定义不等于记录值 |
| 实体类型与校验 | 元数据中的类型和约束，以及应用代码中的业务规则 | 元数据不是所有业务逻辑的替代品 |
| 迁移文件与发布包 | 元数据源码、`.appkg` 与租户安装操作 | 构建、导入和安装有各自的结果；应用安装不等同于部署平台程序 |
| Controller、Service、Repository | 页面请求、应用业务服务、平台适配与公开数据接口 | 类比解释职责，不声称源码必须采用这些类名或层级 |
| 登录、角色、数据过滤 | 认证身份、租户成员、应用准入、权限与数据范围 | 登录成功不能证明已取得某应用或某记录的访问权 |

Getting Started 制作时用 SVG 展示以下解释链，并提供等价的文字说明；这里的文字用于确定图的含义：

```text
便签的对象和字段定义
  → 应用包
  → 安装到练习目标
  → 平台显示字段
  → 保存并重新读取“你好，XRain”
```

每一步展示“输入、执行动作、可见结果、尚未证明的内容”。例如，安装成功仍需核对有效定义和业务访问；课程演示的成功状态不能作为真实环境证据。

字段定义变更放在首课之后，保留记录标识和 API 名称。先验证平台定义变化，再在后续综合练习中检查具体页面是否消费这一属性。课程不能承诺修改元数据标签后所有页面都会自动变化。制作该练习前，由实际消费者确认改动及预期结果；不直接修改共享业务目标。

## 6. 两种学习方式

### 网页内理解与判读

学习者可以在没有业务源码访问权、平台账号或运行环境时完成概念学习。网页提供精简元数据片段、已核验且脱敏的界面材料、请求响应示例、逐步图解和判断题。

交互演示明确标识为教学演示。点击“查看下一步”仅推进案例说明，不发起真实安装。演示保留实际对象关系和失败条件，不模拟未知的平台内部实现。

答题反馈解释推理、证据和常见误判。案例题允许先观察、作答，再展开解释。术语、案例、速查和操作练习分别按用途组织，不强制套用同一个页面模板。

### 真实环境中的开发练习

开发能力练习使用课程维护者核验过的版本组合、正式工具及获准练习目标。入门只下载最小样例；进入实际工程练习时再获取相应业务仓库。练习说明包含实际入口、身份职责、开始状态、每步预期结果、失败后的下一项检查和结束时的恢复方法。

建议使用与共享业务数据隔离的练习目标。目标维护者准备环境和所需权限，学习者在获准的练习范围内执行构建、导入、安装与数据操作；课程网页不代为执行。身份优先复用；需要固定教学身份时，按现有账号台账规则和实际参加人数规划，不按课程会话创建长期随机账号。

网页登录、凭据领取和练习目标参数由受控的环境资料提供。密码、令牌、真实客户数据和个人信息不进入课程正文、静态资源、学习记录或示例日志。

只有网页练习完成时，结果称为“案例判读完成”。真实操作是否完成单独记录，不能由阅读进度或模拟结果自动推定。

### 独立运行与 GitHub 发布

“能运行”分三项验收：课程网站不依赖业务平台即可阅读、搜索、作答和显示 SVG；教学交互在浏览器内正常工作；真实练习在明确提供的获准目标上完成构建、安装和数据回读。前两项不要求平台账号，第三项保留真实平台、身份和工具前置，不能用模拟结果替代。

课程仓库必须包含锁文件、运行版本说明和以下命令入口。它们是待实现的交付契约，当前目录尚不具备这些命令：

| 操作 | 约定入口 | 必须得到的结果 |
|---|---|---|
| 安装依赖 | `pnpm install --frozen-lockfile` | 从提交的锁文件完成安装，不依赖维护者机器上的未声明包 |
| 本地开发运行 | `pnpm docs:dev` | 启动完整课程，输出实际访问地址；首页、导航和交互可用 |
| 内容检查 | `pnpm docs:check` | 检查课程、引用、导航、能力覆盖、SVG 资源及发布范围 |
| 构建正式站点 | `pnpm docs:build` | 生成独立静态产物，失败时返回非零状态 |
| 运行正式产物 | `pnpm docs:preview` | 从已构建产物提供网站；实际页面、资源和交互可用 |

README 从取得仓库开始说明运行版本、上述命令、在线地址、练习材料和已知前置。站点依赖由包管理器安装；不要求全局 skill、相邻业务 checkout、平台源码、业务测试凭据或本机未提交文件。构建阶段不读取浏览器学习记录，学习记录功能在浏览器中执行。

GitHub 仓库必须交付完整课程源、SVG 图源、交互组件、最小样例、锁文件与构建配置。推送后核对远端提交，再从远端取得干净副本重做安装、构建与运行核验。业务源码副本、秘密、真实客户数据、依赖目录和本机构建缓存不进入交付。

在线托管使用 `xingshukeji/xrainTrain` 的 GitHub Pages，预计默认项目网址为 `https://xingshukeji.github.io/xrainTrain/`；这是部署目标推导，当前尚未发布，不能作为已可用网址交付。检查与构建使用同一锁文件；网站发布消费该提交的构建产物。普通内容检查不访问业务平台凭据。记录提交、构建结果、发布结果和实际网址，失败时保留上一个可用版本，通过同一发布入口恢复已核验版本。

Pages 项目路径、课程路由、SVG、样例下载和搜索资源必须使用一致的发布基址。上线后实际打开首页和深层课程地址，刷新深层页面，并检查搜索、SVG 分步操作、练习反馈及本地进度；不能只依据首页返回成功或 Actions 显示成功判断网站可用。[VitePress 部署说明](https://vitepress.dev/guide/deploy)支持构建产物预览及项目子路径配置。

当前目标是公开 GitHub 仓库与公开静态课程，仓库访问范围和网站托管方式不再保留为首版待选项。公开内容仅包含可公开课程、脱敏样例和必要设计；平台源码、凭据及业务内部资料由原系统保管。Pages 提供静态托管，真实练习继续通过原平台执行。[GitHub Pages 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

在线课程中的文档链接必须对目标读者有效。基础学习不能依赖本机 `D:` 路径或相邻仓库链接；私有来源仅作为作者核验依据时，应提供获准的必要教学解释或明确的受管资料入口。真实练习的地址和凭据通过受控渠道提供，不写入静态页面、浏览器存储或发布日志。

首页提供一个默认动作“Getting Started：我的第一条便签”，直接进入完整入门页；架构图、术语表和课程总览不作为开始前的必读内容。另提供“能力地图、接口文档、排错、术语”等查阅入口。实操随相应课程进入，避免形成另一份重复课程目录。左侧课程树保持稳定，当前单元展开；正文的下一课与课程顺序一致。

课程页面重点展示业务问题、实际对象、SVG 流程图、短代码片段和练习。涉及执行顺序、数据往返、状态变化或多个参与者时，优先用 SVG 解释关系；简单事实用文字或表格即可。图示、正文、代码和练习沿用同一组对象与名称。

### SVG 流程图与图示要求

每张图回答一个具体学习问题。Getting Started、接口读写、定义变更与安装生效、权限判断和失败后的处理都应配有必要的 SVG；专题再按需要展示 Trigger 时点、定时执行和外部调用。具体图与课程的对应关系见[能力与接口学习地图](能力与接口学习地图.md)。

- **先核对语义，再绘图**：先确认参与者、起点、动作、输入输出、分支条件与终点。节点和箭头有明确含义，顺序、同步/异步、失败结果和状态变化符合公开合同及已核验行为；缺少依据的内部过程不画成事实。
- **保留影响结果的区别**：构建、导入、安装和记录写入分别表达；请求成功、业务保存与外部送达分别表达。逻辑判断示意不冒充服务端实际执行顺序；闭源平台画公开输入输出，不虚构内部实现。
- **按学习深度展开**：首图只呈现当前例子需要的步骤。相关失败分支在对应解释或交互步骤中展开；省略项说明范围，不能把有条件的流程画成无条件直线。
- **保证可读与可访问**：SVG 使用可缩放布局和清晰文字，箭头不穿过标签，不靠颜色单独区分结果。提供简短图题、可访问名称/描述和等价的文字步骤；在手机和页面放大时核对完整性。
- **动效服务理解**：默认静态图已能表达结论。只有时间或状态变化有教学价值时才增加逐步高亮或动画，提供暂停、重播、键盘操作和减少动态效果的方式；不能用动画假装发出了真实请求。

SVG 资源由培训项目维护。静态图保存在课程资源中，交互图使用课程组件；保留可编辑的图源。来源、适用版本与对应课程一起维护，改动接口或步骤时同步复核图。课程制作须检查实际渲染，不能仅以 SVG 能解析或站点能构建作为通过依据。

### 学习记录

首版建议只把阅读位置、作答和学习者自行标记的练习状态保存到当前浏览器。新增持久状态仅属于培训网站的本地学习记录，不修改平台或 Workforce 数据模型。清理浏览器数据后记录会丢失；站点不宣称提供跨设备恢复、身份认证或经认证的考试成绩。

稳定课程标识用于关联学习记录。大幅修改练习内容时提示重新作答，保留阅读位置；不需要建设成绩后台、学习管理系统或云同步服务。后续确有团队培训管理需求时，再单独设计数据与权限。

## 8. 来源、版本与维护责任

课程可以用自己的语言解释事实，但每个关键机制和操作都需要可以追溯的来源。正式产品规则、API、业务源码和运行操作仍由原项目维护。业务含义引用领域模型与产品契约；当前实现核对源码与实际结果。尚未确认的模型内容不能写成已生效功能。

课程项目在内部维护“能力—来源资料—课程或查阅入口—练习结果—适用版本与核验日期”的对应关系。每项能力有明确学习深度；尚无课程的条目仍提供资料入口，标明是否在当前交付范围。它用于审阅覆盖范围和版本影响，不在网站启动时解析业务文档或连接平台。

接口资料记录所属系统和使用对象，区分公开 HTTP 合同、当前目标的动态目录、SDK 类型、CLI 命令与应用包格式。静态资料说明合同，动态目录说明该目标和身份可发现的内容，真实请求证明本次行为。来源冲突时回到对应所有者核验，不能按更新时间任选一份覆盖其他事实。

课程操作例子标明核验版本；历史响应标明日期及摘录范围。平台接口目录不覆盖所有模块，OpenAPI 入口也须核验可用性。文档覆盖、接口存在、当前身份可调用和完整业务可用分别验证。

已公开或团队可访问的源码使用对应版本的链接。无法访问原仓库的学习者仍可通过课程中的精简材料完成理解课。短教学片段只保留解释所需内容，不成为正式实现副本。

| 责任 | 建议承担者 | 交付内容 |
|---|---|---|
| 学习路线与课程正文 | 培训项目维护者 | 解释、案例、练习、教学交互及内容更新 |
| 业务事实核验 | 对应业务或模型项目维护者 | 确认语义、源码与例子没有误导 |
| 平台操作与契约核验 | 对应平台、应用市场或接入维护者 | 确认菜单、公开接口、安装语义与可观察结果 |
| 练习目标与恢复 | 获准目标的维护者 | 提供已核验目标、身份职责和恢复入口 |
| 课程发布 | 培训项目维护者与目标仓库/托管维护者 | GitHub 仓库、在线目标、构建与发布结果、实际网址和恢复入口 |

以上是职责建议，具体人员尚未指定。课程维护者不能用教学内容改变其他项目的产品规则。

- **覆盖可查**：已纳入的能力和接口资料均可对应课程、查阅入口或明确的后续专题；来源新增或移除时复核地图，不以 skill 数量或目录返回数量证明全平台覆盖。
- **会查接口**：给学习者一个未逐字演示过的简单读取或筛选需求，能够选对文档与接口，说明身份、输入和返回，完成调用并回读结果。
- **事实正确**：字段、接口、版本与截图来自已核验来源；未知内容明确留待核验，不编造菜单或平台实现。
- **流程图正确且必要**：关键流程有对应 SVG，能解释当前学习问题；逐项核对节点、箭头、条件、状态及失败分支与课程证据一致，并核验手机、放大和必要交互。图的数量不作为完成指标。
- **学习效果**：基础课学习者可以解释定义与数据、核对实际版本，并根据证据选择下一项排错动作；交付工程综合练习时，再验证源码和页面消费者的定位能力。
- **真实操作**：只有经过实际目标核验的练习才声明可执行；完成结论区分案例判读、本人操作和维护者复核。
- **使用体验**：默认入口、前后课、术语与搜索可用；关键交互支持键盘和手机阅读；错误及进度状态准确。

实施必须提供第 7 节约定的运行和检查入口。检查链接、导航、术语、媒体、依赖、发布目录，以及能力/资料是否有去向；发布流程使用同一提交的检查与构建结果。外部资料可达性在维护和发布核验时检查，网站基础运行不依赖外部业务服务。行为变更增加定向检查；不以页面长度或测试数量判断教学完成。
