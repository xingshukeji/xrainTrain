# 跟着视频认识平台

先看一遍页面，再跟着做一个小操作。本片依次演示保存便签、创建自定义权限、配置权限集和角色、关联已有成员，以及检查和解除关联。

**第一次接触平台，先看第一章，再去 [G0 保存自己的便签](/start)。** 学到权限时，回来看第二至六章。视频不自动播放；点击章节只定位，准备好后再播放。手机上建议横屏或全屏查看表单。

## 开始跟做之前

便签操作需要已准备的学习视图和本人的读写资格。第二至六章由具有权限维护职责的人操作；普通学员可以观看、读懂关系，不必取得管理员资格。

视频于 2026-10-25 在实际测试平台录制，使用合成便签和课程专用配置。等待与一次误选后的纠正过程已剪去，账号和环境信息已遮盖。每次提交前均核对了选中项；本次成员关联已解除，演示新增的便签及授权配置已清理。不同版本的菜单或标签可能略有变化。

## 认识页面与保存便签 {#便签操作}

1. 进入 **数据视图**，选择“学习便签”。对象和字段已经准备好。
2. 点击 **新建记录**，填写“内容”或“便签内容”，再保存。
3. 在列表中找到自己的那一行，点击 **查看详情**，确认文字仍在。
4. 在详情选择 **编辑**，修改并保存，再核对列表中的新文字。

可观察结果：同一条记录的文字改变了。没有新增字段，也没有重新安装应用包。需要继续接口课时，按 [G0](/start#记录编号) 从详情的“系统标识”中保存自己的 `recordId`。

## 创建自定义权限 {#自定义权限}

进入 **组织与权限 → 权限管理 → 客制化权限 → 新建权限**。“客制化权限”是当前界面使用的名称。

| 填写项 | 视频中的值 | 需要注意什么 |
|---|---|---|
| 权限名称 | `xraintrain.video.read` | 表单已有 `custom.` 前缀，只填后半段 |
| 显示名称 | 课程演示：查看学习成果 | 让维护者能识别用途 |
| 帮助文本 | 说明这是未接入业务动作的课程示例 | 不把名称当成已经生效的业务能力 |

保存后，列表里的完整名称应为 `custom.xraintrain.video.read`。

**这个名称本身不会授予便签读写权限。** 自定义权限需要具体业务功能检查它，才能控制那个动作。对象和字段已有的平台权限，应从实际权限目录选取；二者不可替代。

## 创建权限集并开启权限

1. 打开 **权限集**，搜索 `custom.xraintrain.video`，先确认是否已有同用途项。
2. 本例新建“客制化权限集”，名称填写完整的 `custom.xraintrain.video`，显示名称为“课程演示权限集”。这里与权限表单不同，需要自己写完整前缀。
3. 保存后打开详情的 **权限 → 客制化权限**。
4. 将“授权状态”从“已开启”改为 **未开启**，搜索完整权限名并查询。
5. 打开该行开关，再切回 **已开启**查询，确认出现同一权限。

如果打开开关后该行消失，先看筛选条件：它已不再属于“未开启”。回到“已开启”复查，比再次创建一项同名权限更有用。

## 创建角色并关联权限集

1. 进入 **角色管理 → 新建角色**，本例编码为 `custom.xraintrain.video`，名称为“课程演示角色”。保存并重新打开。
2. 在 **权限集**标签选择 **添加权限集**。
3. 展开选择器，输入“课程演示”，核对候选编码后选中课程权限集。
4. 收起候选列表，确认只选中预期项，再点击 **添加所选**。

可观察结果：角色的权限集列表出现刚才那一项。现在形成了 **角色 → 权限集 → 权限** 的关系，尚未关联任何成员。

## 关联已有成员并核对结果

在角色详情的 **关联用户**中选择 **添加关联用户**，搜索维护者已准备的固定测试成员。核对准确身份、选中并提交；不为演示重复创建账号。

然后在角色的 **权限**中分别检查：

- “客制化权限”出现 `custom.xraintrain.video.read`。
- “对象”权限仍为空，因为本例没有给角色增加便签对象权限。

这次演示证明配置关联已经保存；它没有证明某个业务动作已由这个自定义权限控制。真实业务接入后，还需用本人身份执行对应动作，并核对有权与无权两种结果。

## 解除关联与自己练习

演示结束后，在该成员行选择 **取消关联**，确认关联用户列表为空。撤销这一来源，不代表其他角色或直接权限集授予的资格也会消失。

先暂停视频，不看文字回答：

1. 为什么新建权限后，还要把它放进权限集？
2. 角色中已经有权限集，为什么还要关联已有成员？
3. 为什么本例的“对象权限为空”仍是预期结果？

对照答案：权限集把资格组织在一起；成员通过关联获得这一角色来源；本例只包含未接入业务动作的自定义权限，没有增加对象读写资格。继续到 [B5 · 身份与权限](/basics/access)，把这条关系用于解释实际的 403。
