# 平台能力与扩展选择

**先查已有系统和业务模型，再决定新增什么。** 一项需求可能只需要配置，也可能需要业务服务、页面和工具共同完成。

## 三部分怎样协作

| 部分 | 提供什么 | 定制时补什么 |
|---|---|---|
| XRain | 业务模型、记录、查询统计、组织授权、函数编排、自动化、集成与应用包 | 企业模型、规则、权限、接口映射及环境配置 |
| Workforce | 门户与租户上下文、协作、Task、会话工作区、业务页面与工具接入 | 企业页面、业务服务及所需应用组合 |
| 智能体 Runtime | 智能体定义、模型与工具配置、Session、执行与历史 | 业务指令、工具处理器及任务上下文 |

平台核心源码保持闭源。业务开发使用交付说明、公开接口、公共包导出和项目自身代码。记录 API 中的 Runtime 数据访问与智能体 Runtime 的对话执行是不同用途。

来源：[平台与业务的衔接](https://raw.githubusercontent.com/xingshukeji/skills-hub/main/skills/workforce-business-development/references/platform.md)。

## 从需求选择实现方式

| 需求中的主要变化 | 优先选择 | 需要核对 |
|---|---|---|
| 增加业务记录、字段、关联、列表和简单录入 | XRain 模型、视图与通用记录页面 | 当前对象和系统字段、字段类型、权限、页面是否使用元数据 |
| 在保存前检查规则，或保存后执行动作 | 记录事件与对应业务处理 | Before/After 时机、拒绝与失败结果、执行身份 |
| 到指定时间执行工作 | Routine 与已有执行能力 | 时区、执行成员、调度、实际运行结果 |
| 计算价格、处理复杂状态或使用项目依赖 | 企业业务服务或适用的平台函数 | 输入输出、单位精度、版本、可信上下文 |
| 为现有操作增加自定义交互 | 业务页面与已有服务 | 字段映射、授权、加载与保存、租户切换 |
| 让 AI 查询或处理业务 | 工具声明、宿主处理器和业务服务 | 工具是否装入、执行者权限、参数与真实结果 |
| ERP/CRM 已有数据与操作 | 复用原系统受支持 API | 数据归属、远端身份、映射、失败与未知结果 |
| 原系统为主，增加本地辅助事实 | 混合集成 | 来源系统、租户、外部记录 ID、可编辑方与时效 |

一个元数据字段只有被页面、工具或处理器使用，才会影响相应交互。自定义页面上的固定文字，不会仅因平台字段标签变化而自动更新。

## 一次修改涉及哪些交付物

资源包、业务应用代码、平台租户配置和在线智能体定义分别生效。新增 AI 工具通常涉及声明与处理器接入；只出现工具名称，不能证明处理器已装入。

| 改什么 | 应检查的结果 |
|---|---|
| 对象或字段 | 构建与安装结果、当前 describe、记录读写和原数据 |
| 角色或权限集 | 原用户的允许与拒绝结果、对象/字段/记录范围 |
| 页面或服务 | 实际入口、请求和持久结果、权限与错误 |
| 工具或定义 | 当前定义、宿主接入、实际工具结果、同一业务记录 |
| 外部接口 | 本地请求、远端结果及业务状态；区分失败与结果未知 |
