# 从需求到可验证结果

从用户的业务目标进入所属项目。优先复用已确认的业务主线、接口、模型和接入方式。建模不是每项开发的前置步骤。完整方法见[业务开发技能](https://raw.githubusercontent.com/xingshukeji/skills-hub/main/skills/workforce-business-development/SKILL.md)。

## 先取得足够的上下文

| 要确认的事实 | 从哪里取得 |
|---|---|
| 谁在什么情况下做什么，怎样算完成 | 用户需求、已有业务模型和验收例子 |
| 哪个系统维护原始数据 | 所属项目和原系统接口说明 |
| 已有对象、字段与权限 | 当前平台的对象目录、describe、身份上下文 |
| 应用使用哪些公开能力 | 项目入口、锁文件、公共包导出和类型 |
| 获准操作的环境与身份 | 用户及环境维护者提供的已有配置 |
| 现有实现和必要检查 | 项目源码、测试与真实运行说明 |

文档可读、接口存在和当前身份能调用是不同事实。没有平台环境时，可以继续完成不依赖环境的设计与代码检查，保留未执行项。

## 把需求分成已有能力与实际增量

先选择承载方式，再决定是否涉及模型：

| 当前业务 | 本次开发主线 |
|---|---|
| 原系统已经管理数据、流程与权限 | [配置接口、按需编排并发布业务入口](/developers/integration)，无需先建业务对象 |
| 需要独立管理新的业务事实 | 进入下方模型、数据与权限步骤 |
| 原系统与新增业务并存 | 原接口直接复用，只对新增事实建模，并核对跨系统结果 |

以“员工报修”为例，平台已经提供记录 ID、Owner、审计、历史、分页、授权与支持对象的软删除。新增内容通常是设备、故障描述、状态及业务时间。

维修负责人只有在语义不同于 Owner 时才需要独立字段。提交人、代报修的申请人和维修负责人也可能是不同的人。先明确这些事实，再选择字段和权限。

对于每个动作，写清三项：平台已有实现是什么，需要怎样配置或接入，仍需编写哪段业务逻辑。具体字段与标准能力见[对象基础](https://raw.githubusercontent.com/xingshukeji/skills-hub/main/skills/workforce-business-development/references/object-foundation.md)。

## 模型、数据与权限一起落实

**仅在需要新增或修改 XRain 业务模型时执行本节。** 纯接口转接直接进入[连接现有系统](#连接现有系统)。

1. 查询现有对象和字段，保留稳定 ID 与 API 名。
2. 根据字段类型、长度、精度、选项和关联要求修改模型。
3. 明确业务参与者、允许动作、可读写字段与记录范围。
4. 通过实际发布方式使资源包生效，核对安装版本和当前 describe。
5. 使用原业务角色验证允许与拒绝的结果。

登录、租户成员、应用准入、接口/对象动作、字段访问和记录范围分别判断。界面筛选不提供数据授权。原用户被拒绝时查明具体缺口，不能用管理员成功代替验证。

基础请求见[HTTP 参考](/reference/http)。完整参数与模型规则见[开发资料目录](/ai/reference#模型数据与权限)。

## 页面与 AI 工具共用业务能力

页面和 AI 工具可以调用同一业务服务。服务负责确定计算、状态和保存结果；页面负责交互，AI 负责理解用户输入与解释结果。

SDK 的取得方式、版本与完整读取示例见[官方 SDK](/developers/sdk)。使用当前项目所安装版本的公开导出：

| 导出 | 作用 |
|---|---|
| `@xrain/workforce-application/host` | 宿主启动与应用装配 |
| `@xrain/workforce-application/server` | `XRainRuntimeClient` 等服务端公开能力 |
| `@xrain/workforce-application/client` | 已发布的客户端组件与类型 |
| `@xrain/xrain-agent-runtime/host` | 业务工具调用与执行上下文类型 |

具体导出、选项和组件属性以项目锁定版本的类型为准。声明工具参数时只接收业务输入；执行主体与租户从可信会话或执行上下文取得。

一个只读工单工具的接入需要：

1. 声明工具名称、业务参数与结果含义。
2. 在宿主装入相应处理器，并保留已有工具路由。
3. 从执行上下文取得带当前主体权限的客户端。
4. 调用实际业务读取能力，返回真实内容与状态。
5. 从实际 AI 入口调用工具，核对同一记录和执行结果。

[业务实现参考](https://raw.githubusercontent.com/xingshukeji/skills-hub/main/skills/workforce-business-development/references/implementation.md)提供工具声明、`ServiceToolInvocation` 与处理器接线示例。示例接线不等于完整可部署应用，业务函数、在线定义和宿主装配仍需项目实现。

对于自定义页面，检查平台值到服务返回、再到页面属性的实际映射。平台字段 label 的变化是否显示在页面，取决于页面是否消费元数据；见[真实字段练习](/topics/workforce#追踪一个真实字段)。

## 连接现有系统

ERP/CRM 管理完善且已有查询和提交能力时，使用连接器与请求转接其受支持接口。需要组合、转换或业务判断时，用业务编排调用已登记的 raw 接口，再发布为统一 HTTP 接口。这条路线无需创建 XRain 业务对象或复制原系统模型，详见[免建模的接入指南](/developers/integration)。

先确认远端身份及数据范围，再设计输入输出映射。需要项目依赖的逻辑可以放在企业业务服务中，沿原系统 SDK/API 调用。外部记录 ID 文本不自动成为平台 Lookup。

混合实现需要保存来源系统、租户和外部记录标识，并明确哪些字段由谁修改。远端成功、本地保存成功、消息发送成功分别报告；超时导致结果未知时，先按原系统提供的查询方式确认。

共享连接器凭据代表连接器主体，不能自动等同于当前用户的远端权限。具体规则与失败恢复见[系统集成](https://raw.githubusercontent.com/xingshukeji/skills-hub/main/skills/workforce-business-development/references/integration.md)。

## 根据改动验证结果

| 改动 | 有意义的验证 |
|---|---|
| 记录读写 | 保存后读取同一 recordId；核对字段、空值、查询与相关冲突 |
| 权限与范围 | 用对应角色验证应允许、应拒绝的记录和动作 |
| 页面 | 从真实入口操作，确认请求、错误提示与持久结果 |
| AI 工具 | 检查实际调用参数、执行主体、工具返回及业务记录 |
| 版本升级 | 检查操作与安装版本、当前描述和原记录保留 |
| 外部集成 | 核对远端结果与本地结果，并覆盖与本次修改有关的失败 |

按目标项目现有命令执行适当的源码检查和定向测试。部署、账号变更与对外发送按实际授权办理。交付时分别列出实现内容、实际验证和未验证条件。
