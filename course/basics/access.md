# B5 · 身份与权限

你已经会发请求。现在解释一个常见现象：**登录成功了，为什么仍然不能创建记录？**

本课便签验证时就遇到了这个情况。原维护身份能够安装包、读取元数据，但创建新对象记录返回 `403`，提示缺少 `platform.entity.xrainlearn__note__c.create`。在只授予教学便签所需权限后，同一身份完成了创建与回读。

## 先把四个名称对上页面

| 名称 | 本课用它回答什么 | 视频中的例子 |
|---|---|---|
| 用户 | 谁在使用平台？ | 已有固定测试成员 |
| 角色 | 这个人承担哪组职责？ | 课程演示角色 |
| 权限集 | 这一组职责需要哪些资格？ | 课程演示权限集 |
| 权限 | 允许哪个具体动作？ | `custom.xraintrain.video.read` |

打开[真实操作视频](/platform-tour)，从 1:08 的“创建自定义权限”看起。它连续演示新建权限、在权限集中开启、把权限集关联到角色、关联已有成员，以及保存后核对。

视频里的自定义权限只用于认识配置关系，没有接入业务动作，因此不会自动授予便签读写能力。实际便签使用的是平台派生的对象和字段权限。普通学员观看即可；具有授权维护职责的人再按[文字步骤](/platform-tour#自定义权限)操作。

## 先确认“我正在以谁的身份，访问哪里”

```powershell
$context = Invoke-RestMethod -Uri "$base/api/service/authen/v1/account/context" -Headers $headers
$context | Select-Object tenantId, userId, scope
```

与维护者提供的目标信息核对。不同租户可能存在同名对象、相似页面和同名人物；显示名称相同，不能证明是同一身份。不要把完整会话或令牌贴进问题报告。

## 遇到拒绝时，再逐项定位

先回答三个小问题：身份和租户对吗？要做的具体动作是什么？返回指出哪项资格或范围缺失？下面的表用来定位，不必在第一次阅读时背下全部条件。

![登录、成员、应用、对象字段与记录范围是独立条件；允许动作需要相关条件同时满足](/diagrams/access.svg)

图表示逻辑条件，并不声称服务器按图中顺序调用内部模块。

| 条件 | 判断的问题 | 常见误解 |
|---|---|---|
| 登录 | 这个会话代表谁？ | 有用户名就算已经认证 |
| 租户成员 | 他属于当前租户吗？ | 修改 URL 就能进入另一个租户 |
| 应用准入 | 这个人能进入这个应用吗？ | 能进应用就能读所有记录 |
| 对象与动作 | 能读、创建、编辑还是删除？ | read 自动包含 edit |
| 字段 | 这个字段能读、能写、是否被脱敏？ | 页面藏起来就足够安全 |
| 记录范围 | 能处理这一条具体记录吗？ | 能读对象就能读所有人的数据 |
| 执行身份 | 真正发出数据或外部请求的是谁？ | 配了一个流程就自动拥有管理员权限 |

直接调用记录 API 时，以对应 API 的准入规则为准；只有所用应用入口要求应用准入时，才同时检查那个应用条件。不要凭这张逻辑图给所有接口发明同一套中间件顺序。

## 权限从哪里来

常见组织方式是“已有用户 → 角色 → 权限集 → 权限”，也允许直接给已有用户关联普通权限集。一个用户可以承担多个职责，不需要为每个租户或每个测试任务新建管理员。

教学便签使用独立的 `custom.xraintrain.practice` 权限集，由练习环境维护者配置；权限仅对应 `xrainlearn__note__c` 的相关动作、内容字段和必要系统字段。它不是平台内置的万能角色，也不会给普通测试人物自动授权。

标准对象与字段权限从平台派生目录读取实际名称，不凭拼写相近就认为存在。角色和权限集还可能有多个来源，撤销一个直接绑定后，如果另一个角色仍然授予权限，访问仍可能成功。

## Owner、负责人和创建人

Owner 用于记录归属及相应访问范围；业务负责人是业务关系；创建人记录谁创建了数据。三者可能是同一个人，也可能不同。

把一个字段命名为“负责人”不会自动生成授权。人工分享或共享规则也只解决记录范围的一部分，通常不替代对象动作和字段权限。实际需要协作时继续读[数据维护与分享](/topics/data#记录归属与分享)。

## 自己做一次

1. 读取自己的 context，核对 userId、tenantId、scope；再从 describe 找出当前可创建和可编辑字段。
2. 阅读以下两次**真实验证摘要**，指出差异所在：已授教学便签权限的维护身份读取为 `200`；没有该权限的固定普通测试身份读取同一记录为 `403 / platform.security.permission_denied`。
3. 写出处理 403 的第一项动作：保留当前身份，读实际缺少的权限或范围。若你没有授权维护职责，把这份信息交给维护者，而不是自行改用另一个人的会话。

若培训环境已经准备了两个人物，可由各自本人正常登录复现这组对照。没有准备时使用上述已验证案例，不新建随机账号，也不把管理员的成功结果说成普通用户通过。
