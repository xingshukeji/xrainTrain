# B4 · 字段类型与填写方式

在表单中填写“开会”、勾选“已完成”、选择“工作”，保存的数据并不一样。**字段类型决定可以存什么，API 名是程序使用的字段名称。**

这一课先用便签认识字段，再看两个常见例子：下拉选项和关联记录。

## “内容”和 content__c 是什么关系

你在页面上看到“内容”，通过接口保存时却要写 `content__c`：

```json
{ "values": { "content__c": "下午三点开会" } }
```

| 这一项 | 例子 | 用途 |
|---|---|---|
| 显示名称（label） | 内容 | 告诉使用者该填什么 |
| API 名（fieldApiName） | `content__c` | 程序用它读写字段 |
| 字段类型（type） | `Text` | 这里保存一段文本 |
| 字段值 | 下午三点开会 | 这条便签的具体内容 |

把显示名称改成“便签内容”，请求中的 `content__c` 不变。把输入框改成多行，也只是改变编辑方式；类型、长度限制和权限要分别查看。

## 下拉选项：显示“工作”，保存 work

专题样例有一个“分类”字段 `category__c`，提供两个选项：

| 页面显示（label） | 记录保存（value） |
|---|---|
| 工作 | `work` |
| 生活 | `life` |

选择“工作”后，记录中的这一项是：

```json
{ "category__c": "work" }
```

现在把选项的显示名称从“工作”改成“工作事项”。原记录仍然保存 `work`，页面按照新名称显示“工作事项”。这就是把显示名称和保存值分开的用途。

**写入选项前，先查该字段的 options 接口。** 它告诉你当前有哪些选项、每个选项接受什么值。多选字段保存多个选项组成的数组。接口路径见 [HTTP 速查](/reference/http#元数据与当前身份)。

## 关联字段：保存的是另一条记录的编号

“分类”也可以做成单独的对象。下面用简短编号说明关系；真实操作使用平台返回的 `recordId`。

| 分类记录编号 | 分类名称 |
|---|---|
| A01 | 办公用品 |
| A02 | 差旅 |

一条“购买笔记本”的账目选择“办公用品”后，关联字段保存 **A01**。以后把分类名称改成“办公耗材”，账目仍指向 A01，不需要逐条修改账目。

这种字段叫 **Lookup（关联字段）**。它与前面的下拉选项有一个关键区别：

- 下拉选项选择预先配置的值，例如 `work`。
- 关联字段选择另一个对象中的记录，保存那条记录的 ID。

人员字段 `UserRef` 用来选择人员。它使用专门的人员候选接口和权限检查，实际接入时按人员字段的说明处理。

## 其他常见类型，按需要查

| 要保存的信息 | 类型 | 通过数据接口提交的例子或规则 |
|---|---|---|
| 短文本、长说明 | `Text`、`LongText` | `"下午三点开会"`；遵守长度限制 |
| 是否完成 | `Boolean` | `true` 或 `false`，不加引号 |
| 数量 | `Number` | 数值，例如 `3`；遵守字段的取值限制 |
| 金额、精确小数 | `Money`、`Decimal` | XRain 数据接口使用字符串，例如 `"10.20"` |
| 某一天 | `Date` | 例如 2026-10-25；它本身不表示几点 |
| 某个时刻 | `DateTime` | 需要明确时区；按对象返回的 `temporalContracts` 处理 |

金额用字符串传输，是为了保留十进制精度。不要先把它转成 JavaScript 浮点数再计算。上表讲的是数据接口；应用包内的初始数据格式要另查包格式说明。

日期和时刻的详细例子见[时间与执行人](/topics/automation#时间与执行人)。暂时只处理文本时，可以用到这些类型再查。
