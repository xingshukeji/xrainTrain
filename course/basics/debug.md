# B7 · 出错后继续

独立开发不要求一次写对所有请求，但要求能找到第一处偏差。**把“我以为会发生什么”和“实际返回了什么”并排放好。**

<FlowSteps />

## 用便签认识几类错误

| 现象 | 已知含义 | 下一项检查 |
|---|---|---|
| `401` | 会话、身份来源或认证方式不被接受 | 正常登录，核对会话到期与接口允许的认证方式 |
| `403 / platform.security.permission_denied` | 当前身份缺少实际操作所需权限或范围 | context、具体权限名、字段与记录范围 |
| `400 / platform.data.validation_failed` | 本次必填内容为空等输入不满足规则 | describe 的字段类型与必填约束 |
| `404` | 此路径或记录当前不可取得 | 对象代码、真实 recordId、租户与删除状态；不能直接断言全局不存在 |
| `409 / platform.data.concurrency_conflict` | expectedValues 中的旧字段值不再匹配 | 保留自己的新内容，重读并处理差异 |
| `5xx` | 服务端未能正常处理 | 保留 traceId、时间与脱敏请求，按服务问题处理 |
| 网络超时 | 没有取得确定响应 | 先查同一操作或可定位结果，不自动重复写入 |

这张表没有承诺“所有校验错误一定返回 400”。旧资料中存在 Text 超长返回 500 的记录；当前目标遇到什么，就如实保留什么，不能把服务错误改写成空列表或成功。

## 一个可自己完成的定位题

下面请求会向便签对象写入一个未定义字段：

```json
{ "values": { "contents__c": "你好，XRain" } }
```

你预期保存内容，但有效字段其实叫 `content__c`。先在 describe 查字段名，再对照输入；不要先新增 `contents__c` 来迁就拼写错误。

第二个问题：创建时只传 `{ "values": {} }`。本课程在测试目标上得到了 `400 / platform.data.validation_failed`。原因是已安装字段 `required=true`，不是登录失败。分别解释这两个错误后，再用正确值创建或更新自己的教学记录。

## AI 可以帮你检查什么

给 AI 一个有边界的问题，比让它猜环境更容易得到可用结果：

```text
我在已授权测试租户更新自己的学习便签。
对象 xrainlearn__note__c，字段 content__c，Text，必填。
方法 PUT，路径是记录接口，记录 ID 已核对。
values.content__c 是“今天学会回读”。
expectedValues.content__c 是我先前读到的“你好，XRain”。
实际返回 409，errorCode 是 platform.data.concurrency_conflict。
请解释下一步应读取什么，以及怎样保留尚未保存的文字。
不要建议扩大权限、删除并发条件或重复安装。
```

检查 AI 回答是否引用了当前接口合同，是否区分事实与猜测。代码可以由 AI 辅助起草，但目标、身份、写入影响和实际返回仍须由你核对。平台源码闭源不妨碍使用公开 HTTP、SDK、元数据和返回结果完成这项判断。

## 自己做一次

1. 从自己遇到的错误或上面两个例子中选一个，写下方法、字段、预期、实际状态和错误码。
2. 从[按现象排错](/help/errors)选择第一项检查，说明为什么不是另一项。
3. 修正一处输入或处理差异后，回读同一目标验证结果。

完成标准：别人只读你的脱敏记录，就能理解问题落在目标、身份、字段、状态还是服务，不需要你重新口述全部过程。
